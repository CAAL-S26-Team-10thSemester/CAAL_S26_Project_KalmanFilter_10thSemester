1 Purpose of this Milestone
Milestone 4 is the final stage of the Kalman Filter project. Building directly on the scalar
RISC-V assembly implementations from Milestone 3, students willvectorisethe core compu-
tational functions of both the Linear Kalman Filter (LKF) and the Extended Kalman Filter
(EKF) using theRISC-V Vector (RVV) extension.
2 RISC-V Vector Extension (RVV)
The RISC-V Vector Extension (RVV) introduces vector registers and instructions to operate
on multiple data elements simultaneously.
2.1 Vector Registers
•32 vector registers:v0 -- v31
•Configurable vector length (VL)
•Supports element-wise operations
2.2 Relevant Vector Instruction Classes (Not Limited to)
•Configuration:vsetvli,vsetivli,vsetvl.
•Unit-stride load/store:vle64.v,vse64.v.
•Strided load/store:vlse64.v,vsse64.v(required for transpose and column-wise
access).
•FP arithmetic — vector×vector:vfadd.vv,vfsub.vv,vfmul.vv,vfdiv.vv.
•FP arithmetic — vector×scalar:vfadd.vf,vfsub.vf,vfmul.vf,vfdiv.vf.
•Fused multiply-accumulate:vfmacc.vv,vfmacc.vf,vfmsac.vv,vfmsac.vf.
•Square root:vfsqrt.v.

6 Memory Management
The additional consideration in Milestone 4 isalignment: RVV unit-stride loads (vle64.v)
do not require alignment beyond the element size (8 bytes), but performance degrades on
some implementations for unaligned accesses. Students must confirm that all pointers are
passed to vectorised kernels are 8-byte aligned and discuss whether 64-byte (cache-line)
alignment would further improve throughput.
